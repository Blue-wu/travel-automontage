# 旅行 Vlog 画面字幕

## 第一步：读规范正文

**必须先读 `skills/travel-copywriting.md`**（项目根目录下），那是唯一事实来源。
本文件只定义交互协议，判据、五种手法、禁用清单、字数约束全在正文里。

若当前目录不是 travel-automontage 项目，向用户索取该文件，或直接按下列摘要执行：

- **判据**：遮住字幕只看画面，观众能猜到的就是废的
- **手法**：A 场景误读 / B 宏大降格 / C 身份错位 / D 数值荒诞 / E 错位归因
- **控制**：每片手法只用 2-4 处，其余写平实句；覆盖率 40-60%
- **字数**：<1.5s 留空、1.5-2.5s ≤6 字、2.5-4s ≤10 字、>4s ≤14 字

## 第二步：拿到镜头信息

支持三种输入，按用户给的形式走，**不要强求格式**：

| 输入形式 | 处理 |
|---|---|
| `edit_decision.json` / 时间线 JSON | 读 `timeline[]`，取 `duration_sec` / `visual_summary` / `visual_tags` |
| 手写镜头表（"1. 航拍草原 3秒"） | 直接用 |
| 只有口头描述（"我拍了新疆的湖和草原"） | 先问清镜头数量和大致时长，或直接给一版让用户挑 |

## 第三步：问三个问题（缺了就只能写平实句）

手法 B/D 的原料只能来自创作者，自动拿不到：

1. 这趟原计划是什么？和实际有什么出入？
2. 哪个瞬间最不舒服？（冷、累、堵、干等）
3. 为什么去这一趟？

**用户不想答就不要追问**，直接按现有信息写，但要说明"缺少行程背景，手法 B/D 用不上"。

## 第四步：输出

给一张表，不要给 JSON（除非用户要求接入代码）：

| # | 时长 | 画面 | 字幕 | 手法 | 为什么猜不到 |
|---|---|---|---|---|---|

规则：
- 留空的镜头也要列出来，标 `—`，让用户看到留白是刻意的
- 每条有字的都标手法字母；标不出手法的就是套话，重写
- 结尾附一行自检：手法用了几处、覆盖率、首尾呼应是哪两条

## 第五步：自检后再输出

逐条问自己"遮住这条字幕，我会猜它写什么"。猜中了就重写。
**写不出错位就写平实事实，绝不退回抒情套话。**

## 常见追加请求

- "再来一版" → 换手法组合，不要换同一手法的近义句
- "太尬了" → 减少手法处数（降到 2 处），其余改平实
- "太平了" → 加一处，优先加在开场和结尾
- "字太多" → 按时长上限硬砍，或把长句挪到更长的镜头
